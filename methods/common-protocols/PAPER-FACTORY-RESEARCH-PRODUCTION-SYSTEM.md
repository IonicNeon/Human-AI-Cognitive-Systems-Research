# Paper Factory — Governed Research Production System

**Status:** active operating design  
**Public class:** `NONEMPIRICAL-METHOD`

## Purpose

Research questions can emerge faster than a paper-by-paper workflow can safely manage. A paper is not merely prose; it is a governed bundle of question, theory, evidence, methods, analysis, claims, figures, privacy decisions, review history, and release state.

The program therefore treats research production as a reusable governed system.

## Canonical unit

Every materially distinct research object receives a stable `IF-R###` identifier in `research-registry.yml`. Publication numbers are assigned separately and may change without changing research identity.

The permanent physical home is:

```text
studies/IF-R###-slug/
```

A mature public study may contain:

```text
README.md
study.yml
protocol/
claims/
literature/
data-public/
analysis/
figures/
outputs/
provenance/
```

Directories should be created when releasable material exists rather than as empty ceremony.

## Research lifecycle

1. **Spawn** — record the trigger observation, limitation, method, or theory and parent research IDs.
2. **Triage** — decide whether the object is a subquestion, dataset, instrument, analysis, or independent research object.
3. **Prespecify** — freeze research question, unit, evidence rules, outcomes, exclusions, stopping logic, and validity threats before confirmatory results are inspected.
4. **Collect** — preserve source evidence and immutable provenance in the appropriate private or public environment.
5. **Adjudicate** — decide inclusion before aggregate narrative construction where feasible.
6. **Analyze** — deterministic scripts first; exploratory outputs explicitly labeled.
7. **Write** — manuscript statements remain downstream of claim/evidence state.
8. **Adversarial review** — attack definitions, alternative explanations, causal strength, privacy, and reproducibility.
9. **Public-safe derivation** — transform rather than mirror private evidence into releasable artifacts.
10. **Release** — version paper, public data, code, figures, disclosures, and lineage state together.
11. **Spawn again** — register new research generated by results, failures, or limitations.

## Evidence and claim discipline

Dependency states:

- `FIXED`
- `PROVISIONAL`
- `PENDING-CORPUS`
- `PENDING-ADJUDICATION`
- `PENDING-EXPERIMENT`
- `SIMULATED-ONLY`

Publication-facing classes include:

- `NONEMPIRICAL-METHOD`
- `CURRENT-BOUNDED-RESULT`
- `EXPLORATORY-RESULT`
- `CONFIRMATORY-RESULT`

Claim maturity cannot exceed the weakest unresolved dependency. Manuscript wording must not silently upgrade evidence state.

## Research-lineage discipline

For new research, preserve at least:

- `spawned_at`
- `spawned_by_research_id`
- `spawn_trigger_type`
- `trigger_observation`
- `prospective_or_posthoc`
- `existing_evidence_at_spawn`
- `new_data_required`

This makes the evolution of the science itself auditable and separates prespecified hypotheses from post-hoc explanations.

## Validation checks

Automate where practical:

- valid and unique research IDs;
- valid parent IDs and controlled relation types;
- empirical claims linked to eligible evidence state;
- causal language compatible with the supported causal class;
- figures/tables regenerated from code and data;
- analysis output records code/input versions or hashes;
- hidden answer keys excluded from public release;
- obvious private-source markers excluded from public derivatives;
- references resolvable where identifiers exist;
- AI-use and human-contribution disclosures present when relevant;
- method amendments versioned after data inspection.

## Literature workflow

A reusable literature matrix should capture at least:

`source_id, citation, construct, method, population_or_system, finding, limitation, relevance_to_IF_R, transferred_claim, nontransferable_boundary, checked_date`

Literature defines constructs and comparison classes; it should not be used to retrofit fashionable terminology onto observed results.

## Reproducibility manifest

Quantitative releases should be able to identify:

- input dataset hashes;
- analysis code SHA;
- environment/dependency record;
- generated figure/table hashes;
- excluded rows and reasons;
- missing-data accounting;
- exploratory/confirmatory label;
- exact command used.

## Manuscript rule

The manuscript is a **view over governed research state**, not the source of truth. Change evidence/data/claim state first; update prose second.

## Public repository rule

This repository receives only approved public derivatives. `data-public/` is the only public study-data namespace. Raw private evidence must never be staged here, including temporarily.
